ABOUT MAILGUARD

A practical second look at suspicious email.

An educational detection workflow that combines a trained text model with visible message signals.

01

How analysis works

Message text is passed to the local Python service through the Java application API. The selected scikit-learn pipeline combines word and phrase patterns with message and URL indicators. A rule-based pass reports configured urgency, credential, financial, and URL patterns.

02

Datasets

The model workflow uses both included CSV files. The email dataset supplies subject, sender, and body text with numeric labels. The message dataset supplies short text with ham/spam labels. Spam is treated as a phishing-like class for this educational model.

03

Architecture

Browser interface → Spring Boot REST API → Flask prediction API → scikit-learn model. Java stores detection history in a local H2 database. The browser never calls Flask directly.

04

Responsible use

Model confidence is not proof of malicious intent. The service does not browse, resolve, or open submitted URLs. URL indicators describe visible formatting only; they do not establish reputation or safety. Confirm sensitive requests using a known contact method.
