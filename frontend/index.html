01 · DETECTION FLOW

How phishing detection works

The browser sends message text to Spring Boot, which calls the Flask prediction API and returns the model response. The browser does not call Flask directly, and analysis results are not stored.

Browser→Spring Boot→Flask + scikit-learn

02 · MACHINE LEARNING

Trained text model

The deployed Random Forest classifier looks for patterns learned from the project’s training data. Reported probabilities are model confidence and are not calibrated guarantees.

03 · URL ANALYSIS

Links stay unopened

URLs are parsed as text for visible traits such as IP hosts, shorteners, unusual length, deep subdomains, and possible lookalike spellings. Links are never visited.

04 · LANGUAGE SIGNALS

Configured phrases

Rule checks look for urgency, credential requests, financial requests, and threat or reward language. These indicators add context; they are not proof of intent.

05 · RISK ASSESSMENT

Evidence-based summary

Risk levels reflect the model classification and configured keyword or URL indicators. The result includes the reasons and signals that were found.

!

06 · LIMITATIONS

Use the result as a signal, not a verdict.

Datasets may not represent every mail style or attack. A message can be misclassified, and a low-risk result does not establish that it is safe. Confirm sensitive requests through a trusted channel.
